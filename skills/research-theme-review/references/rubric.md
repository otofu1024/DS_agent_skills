# 評価基準

6つの基準それぞれについて、「強い」「弱い」「不明」のどれかを付け、根拠を書く。「不明」が残ったら、何を調べれば決まるかを書く。

## 1. 新規性

問い:

- 最も近い先行研究と比べて、モデル・問題・手法・結果のどれが新しいか
- 同じ手法が隣接分野（理論、システム、ブロックチェーン、DB）で既に使われていないか
- 直近の論文（プレプリントを含む）で同じことが行われていないか

強い: 最も近い先行研究を ID つきで挙げたうえで、結果か手法に明確な差がある。
弱い: 差がモデルの小さな変更だけ。既存の最適化の組み合わせだけ。
不明: 検索が足りない。隣接分野を調べていない。

## 2. 重要性

問い:

- 解けると、誰の何が変わるのか（理論の未解決問題が閉じる、配備中のシステムの問題が消える、など）
- 理論なら、既存の上界と下界の間の隙間を埋めるか。新しいモデルなら、そのモデルを考える理由があるか
- システムなら、改善は実際の負荷や配備条件で効くのか。どのくらいの規模で効くのか

強い: 問題の存在を示す根拠（論文、障害報告、既知の未解決問題）がある。
弱い: 「既存手法より速い」だけで、なぜ速さが重要なのか、どの条件で効くのかが言えない。

## 3. モデルの妥当性

問い:

- system-model-spec スキルのモデルカードで、結論を左右する項目が決まっているか
- 仮定は強すぎないか（同期を仮定している、信頼できる部品を仮定している、敵対者を弱くしている）
- 仮定は弱すぎないか（弱すぎて既知の不可能性に当たる）
- 比較相手と同じモデルで比べているか

強い: モデルが明示され、仮定の理由がある。
弱い: 仮定が暗黙のまま結論に効いている。

## 4. 既知の結果との整合

問い:

- 主張は FLP、DLS、Dolev–Reischuk などの不可能性・下界と矛盾しないか（system-model-spec の references/known-results.md）
- 下界に「勝つ」主張なら、どの仮定が違うから勝てるのかを言えるか
- 既知の上界（既存のプロトコルが達成している値）を超える必要があるのに、超えていない、ということはないか

強い: 関係する既知の結果を挙げ、矛盾しない理由を説明できる。
弱い: 既知の結果を確かめていない。または矛盾の説明がつかない。

## 5. 検証可能性

主張をどうやって示すかを具体的に書く。示し方が言えないテーマは採用しない。

理論の研究:

- 証明の筋道（どの補題が要るか、どの既知の技法を使うか）
- TLA+ でモデル検査できるか（小さな n と f で safety を確かめる。tla-plus-model-check スキルを使う）
- Lean で機械的に証明する価値があるか、その規模はどのくらいか（lean-consensus-proof スキルの雛形にある quorum の交差の補題から始められるか）

システムの研究:

- 比較相手（ベースライン）とその実装（既存の実装があるか）
- 負荷のかけ方、指標（スループット、レイテンシの分布、故障からの回復時間）
- 故障の入れ方（リーダーの停止、ネットワークの分断、遅延の注入）
- 正しさの確かめ方（linearizability の検査、Jepsen など）

強い: 何をすれば主張が示せるか、何が出れば主張が否定されるかが具体的に言える。
弱い: 「実装して評価する」「証明する」だけで中身がない。

## 6. 実現可能性

問い:

- 必要な技能と道具（形式検証、実装、実験環境）は何か。今の技能との差はどのくらいか
- 必要な計算資源や実験環境（多数のマシン、地理分散）は手に入るか
- 期間内に、最小限の成果（小さな定理、プロトタイプと1つの評価）まで行けるか

強い: 最小限の成果までの道筋がある。
弱い: 必要な前提（大規模な実験環境、未解決の補題）に依存している。
